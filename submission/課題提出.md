# 天気予報アプリ「tennki」 課題提出レポート

## アプリ概要
Next.js (App Router) + TypeScript + Tailwind CSS で作成した天気予報アプリ。
都市名検索・現在地取得で天気を取得し、カレンダーから日付を選んで予報を確認できる。

---

## 工夫したポイント

- 都市名検索と現在地取得(Geolocation API)の2通りの入力方法に対応し、使いやすさを優先した
- OpenWeatherMapのGeocoding APIから `local_names.ja` を取得し、都市名を日本語表示にした
- 3時間ごとの予報データを日付単位に集計し、各日の「代表値」(12時 or データの中央)を選んで見やすくした
- カレンダーの各日付に天気アイコンを表示し、クリックしなくても一目で天気の傾向がわかるようにした
- 予報データが存在しない日はカレンダー上でクリック不可にし、誤操作を防いだ
- ダークモード対応のスタイリングをあらかじめ組み込んだ
- APIキーは `.env.local` に分離し `.gitignore` で除外、サーバー側(API Route)のみで利用しクライアントに漏れない設計にした

---

## 開発の流れ

1. `create-next-app` でプロジェクトを初期化
2. `src/lib/types.ts` でデータ構造(型)を先に設計
3. `src/app/api/weather/route.ts` でOpenWeatherMapと連携するAPIルートを実装
   (都市名→緯度経度変換 → 予報取得 → 日付ごとに集計)
4. UIを `SearchBar` / `Calendar` / `WeatherCard` のコンポーネントに分割して実装
5. `page.tsx` で状態管理(検索・選択日・ローディング・エラー)をまとめて画面を構成
6. 実際にサーバーを起動し、curlでAPIレスポンス、Playwrightでブラウザ操作を確認
7. フィードバックをもとにカレンダーへ天気アイコン表示機能を追加

---

## 技術的な学び

- Next.jsのAPI Routes (`route.ts`) を使うと、APIキーなどの秘密情報をクライアントに渡さずサーバー側だけで扱えること
- 外部APIの生データ(3時間ごとの予報)を、UIで使いやすい形(日付ごとの配列)に変換するデータ加工の考え方
- `navigator.geolocation` を使った現在地取得と、許可されなかった場合のエラーハンドリングの書き方
- 先に型(TypeScript)を設計してからAPIとUIを実装すると、連携ミスが減ること
- Playwrightなどのブラウザ自動操作ツールを使うと、人の目視確認だけでなく機械的にUI動作を検証できること

---

## 開発の進め方の学び

- 「実装した」で終わらせず、実際にサーバーを起動してAPIやブラウザ操作で動作確認することの重要性
- スクリーンショットを撮って目視確認すると、コード上は正しくても見た目のズレ(アイコンが小さすぎる等)に気づける
- 機密情報(APIキー)は最初から `.env.local` + `.gitignore` で管理し、誤ってコミットしないよう徹底する習慣
- 小さな機能追加でも「コンポーネントの責務を分ける」(Calendarは表示のみ、データ取得はpage.tsx側)ことで変更がしやすくなる
